# 方案详述（初赛附录材料）

> 本文件是《作品简介》的配套详述，随 AgentTeams 代码包提交；初赛平台仅提交 500 字内简介正文。

## 附录 A：Agent Identity 清单（8 个 Agent）

### A1. lead-intake（线索聚合 Agent）

| 字段 | 内容 |
|---|---|
| Name | lead-intake |
| Role | 线索入口与多渠道会话聚合者，承担闭环第 1 环（任务输入） |
| Capabilities | 能：多渠道归并去重、线索分级、状态机初始流转（L0）；不能：承诺报价与优惠、跨渠道合并不同客户、编造会话内容 |
| Inputs | 多渠道会话文本（官网/微信/电话/短视频/门店）、线索元数据、客户基础信息 |
| Outputs | 归并线索（lead_id、来源渠道、需求摘要、初始分级、证据引用），JSON 契约 |
| Dependencies | 下游 profile-builder；Skill：lead-fusion、profile-building；工具：mock_crm / mock_wechat / mock_knowledge |
| Decision Boundary | 自主：归并去重与分级建议；人工：身份存疑会话不强制合并；投诉/价格异议升级 strategy-planner |
| Trace | 每次工具调用写入 Trace（时间/工具/参数/结果预览），归并结论带证据引用，可回放审计 |

### A2. profile-builder（客户画像 Agent）

| 字段 | 内容 |
|---|---|
| Name | profile-builder |
| Role | 客户画像构建者，承担闭环第 2 环（需求分析） |
| Capabilities | 能：画像字段推断与置信度标注、历史记忆召回、相似案例参考；不能：推断征信/收入敏感字段、单渠道下结论、编造需求 |
| Inputs | 归并线索、客户历史互动记录（Agent 记忆存储）、相似成交案例（RAG） |
| Outputs | 结构化画像（家庭结构/预算/用车场景/偏好/决策角色）+ 置信度 + data_gaps + 证据引用 |
| Dependencies | 上游 lead-intake；下游 intent-analyst、strategy-planner；Skill：profile-building、deal-memory |
| Decision Boundary | 自主：画像推断与置信度；人工：置信度 < 0.5 标注"信息不足"，不驱动策略生成 |
| Trace | 画像字段带证据引用，data_gaps 供下游降级处理 |

### A3. intent-analyst（购车意图识别 Agent）

| 字段 | 内容 |
|---|---|
| Name | intent-analyst |
| Role | 购车意图与分级判断者（方向二"意图识别与自动分类分级"） |
| Capabilities | 能：信号字典打分、购车阶段映射、跟进优先级建议；不能：单信号定高意向、把未回复当负向信号、放弃低意向线索 |
| Inputs | 结构化画像、会话购买信号文本、意向分级 SOP |
| Outputs | intent_score、stage、priority、signals、recommended_action、evidence_refs |
| Dependencies | 上游 profile-builder；下游 strategy-planner、customer-ops；Skill：intent-scoring、deal-memory |
| Decision Boundary | 自主：评分与分级；人工：低意向标记 nurture 交 customer-ops 周期触达，不直接放弃 |
| Trace | 评分过程输出信号清单与权重，支持 AgentLoop 离线评估意图识别准确率 |

### A4. strategy-planner（销售策略生成 Agent）

| 字段 | 内容 |
|---|---|
| Name | strategy-planner |
| Role | 销售策略与方案制定者，承担闭环第 3 环（处理方案生成） |
| Capabilities | 能：车型推荐（对比矩阵+理由）、标准报价、跟进路径设计、风险等级标注（L0-L3）；不能：编造政策/补贴、推荐无库存车型不标注、画像不足时强行推荐 |
| Inputs | 画像 + 意向分级、车型目录与库存、报价/补贴政策、历史成交案例（RAG） |
| Outputs | 策略（推荐清单/跟进路径/报价/风险分级）+ 证据引用 |
| Dependencies | 上游 profile-builder、intent-analyst；下游 negotiation-executor；Skill：car-recommendation、quote-pricing、deal-memory |
| Decision Boundary | 自主：推荐与路径设计；人工：报价严格执行政策授权，保险/合同条款只建议不承诺 |
| Trace | 推荐理由引用 RAG 证据（产品文档/案例 ID），风险分级随策略输出 |

### A5. negotiation-executor（智能议价 Agent）

| 字段 | 内容 |
|---|---|
| Name | negotiation-executor |
| Role | 议价与动作执行者，承担闭环第 3-4 环（方案执行 + 结果核验前置） |
| Capabilities | 能：授权内优惠自动应用（L1）、试驾预约（可逆）、金融方案对比、模板话术；不能：承诺授权外优惠、未授权征信查询、重复让步、超授权静默放行 |
| Inputs | 策略输出、报价政策与授权额度、议价底线、试驾档期、金融产品目录 |
| Outputs | executed 动作清单、approval_created 审批任务、escalation 交接单、rollback_points、evidence_refs |
| Dependencies | 上游 strategy-planner；下游 order-executor；Skill：quote-pricing、negotiation-guard、test-drive-booking、finance-plan |
| Decision Boundary | 自主：授权内优惠/试驾/金融方案；人工（转人工条件）：优惠超授权、触及底线、合同/保险异议、情绪化投诉 |
| Trace | 每步让步记录（金额/授权额度/剩余额度/依据）写入 actions 与 Trace，转人工输出结构化交接单 |

### A6. order-executor（订单执行 Agent）

| 字段 | 内容 |
|---|---|
| Name | order-executor |
| Role | 订单执行与闭环验证者，承担闭环第 4-5 环（动作执行 + 结果验证） |
| Capabilities | 能：库存预留（L1 可逆）、订单草稿创建（幂等）、状态跟踪、回滚、成交验证（check_deal）；不能：绕过审批确认订单、重复创建订单、无证据承诺交付 |
| Inputs | 执行结果（报价/优惠/审批状态）、客户成交确认、库存预留需求 |
| Outputs | 订单状态报告（order/order_key/status/rollback_point/deal_verification） |
| Dependencies | 上游 negotiation-executor；下游 knowledge-miner；Skill：order-safe-execute、deal-memory |
| Decision Boundary | 自主：草稿创建/状态跟踪/回滚；人工：合同签署与交付必须审批，金额超门槛只生成草稿与审批任务 |
| Trace | 创建/回滚/审批动作全部入 Trace，check_deal 结果作为闭环证据供复盘 |

### A7. customer-ops（客户运营 Agent）

| 字段 | 内容 |
|---|---|
| Name | customer-ops |
| Role | 售后运营与再营销者（方向二"结果核验与客户满意度确认"外延） |
| Capabilities | 能：标准模板触达（关怀/续保/保养/活动，L1）、触达节奏、复购激活；不能：向拒绝营销客户推广、非模板内容互动、触达中承诺优惠 |
| Inputs | 成交/流失/培育线索状态与画像、客户历史互动、售后权益与运营 SOP |
| Outputs | 触达计划（channel/template/status）、复购激活方案、referral_potential、evidence_refs |
| Dependencies | Skill：profile-building、deal-memory、case-mining；工具：mock_crm / mock_wechat / mock_knowledge |
| Decision Boundary | 自主：标准模板触达与节奏；人工：优惠承诺/投诉/个性化大额权益触达转人工 |
| Trace | 触达动作（模板/参数/客户/时间）入 Trace，运营效果回流为评估指标 |

### A8. knowledge-miner（知识沉淀 Agent）

| 字段 | 内容 |
|---|---|
| Name | knowledge-miner |
| Role | 知识沉淀与经验回流者，承担闭环第 8 环（经验沉淀） |
| Capabilities | 能：案例要素提炼、增量价值判断、脱敏后入库（L0）；不能：原始敏感会话直接入库、对未验证失败原因下结论、直接修改策略/SOP |
| Inputs | 成交闭环报告（TeamLeader 汇总）、工具调用 Trace 与 actions（执行证据）、既有案例库 |

## 附录 B：Skill 清单（11 个）

### B1. lead-fusion（线索归并）

| 字段 | 内容 |
|---|---|
| Skill 名称 | lead-fusion |
| Skill 类型 | 自定义 Skill（企业系统集成能力） |
| 使用场景 | 多渠道客户咨询归并去重、形成统一线索池（闭环第 1 环） |
| 输入参数 | 多渠道会话列表（channel/customer_id/time/text/owner）、线索元数据 |
| 输出结果 | 合并线索（lead_id、来源渠道、去重摘要、初始分级、证据引用） |
| 调用条件 | lead-intake 收到新会话流或出现 2+ 条疑似同客户会话时 |
| 依赖工具/系统 | mock_crm（list_sessions/get_lead/update_lead_stage）、mock_wechat；迁移 MCP 后对应 crm.lead.query |
| 失败处理 | 会话缺客户 ID 按时间窗口启发式归并并标注置信度；歧义保留候选转人工 |
| 权限与安全 | L0 只读；会话内容脱敏后进入下游，禁止输出完整电话号码 |
| 复用价值 | 可复用于保险、房产、高客单价零售等任何多渠道线索型业务 |

## 附录 E：MCP 等价集成契约与迁移路径

- 协议：HTTP REST，`POST /tools/{scenario_id}/{tool_name}.{function_name}`，JSON 请求/响应，`{"ok": true, "result": ...}` 统一包装。
- 鉴权：网关侧 API Key 校验（Higress 统一入口），Worker 侧无密钥直接暴露。
- 输入输出 Schema：见 tools/tool_catalog.json（8 类工具、函数清单、参数与返回结构），每函数含 future_mcp_mapping 映射名。
- 错误处理：非 2xx 统一错误包装；函数级失败重试一次；审批超时按未批准处理（不默认放行）。
- 审计记录：每次调用写入 Trace（时间/工具/参数/结果预览）+ actions（幂等键、审批状态）。
- 迁移成本：工具调用链已按"工具名.函数名"命名空间组织，future_mcp_mapping 已预置（如 crm.lead.query、pricing.discount.apply、order.create），迁移到 MCP Server 仅需协议适配层替换 HTTP 适配器，业务 Skill 与 Agent 零改动。
